# Desk panel — structure for contributors

The Kettle **Desk** is the primary sitting surface in the editor host. It lives in the **Secondary Side Bar** (opposite Explorer) and is implemented almost entirely in one module:

| Layer | File | Role |
|-------|------|------|
| Host glue | `src/extension.ts` | Commands, project resolve, HTTP via `api.ts`, injects `DeskPanelDeps` |
| Webview shell | `src/deskPanel.ts` | HTML/CSS/JS template + message protocol; ritual UI |
| Sitting state | `src/state.ts` + `src/ritualParity.ts` | Ephemeral selection and tested canonical ritual decisions — not a desk DB |
| Confirm cards | `src/confirmCard.ts` | Parse/serialize founding GFM checklists |
| Queue list | `src/queueView.ts` | Explorer TreeView — relative paths, file icons, handled last (approved struck, set-aside dimmed), Approve inline, Not this / Bring back in the context menu |
| Editor chrome | `package.json` menus + `extension.ts` context keys | Title-bar Approve / Comment / Finish batch (`kettle.sweep`); keybindings `⌘⇧A` / `⌘⇧;` / `⌘⇧Enter` |

Core owns the desk on disk (`.kettle/`) and the HTTP contract (`kettle-core/API.md`). This package is a viewport.

## Ritual actions (do not invent peers)

Every label, hint and status line on screen comes from core's catalog (`src/uiCopy.ts`, generated by `npm run sync-ui-copy`) through `ritualParity.ritualControls` / `deskStatusLine`. House words — desk, sitting, sweep, ruling, charter, founding, brief, curator — stay in code and docs; they never reach the screen (kettle-core `docs/UI.md` § Who the words are for).

| Button (catalog key) | Core route | Meaning |
|--------|------------|---------|
| **Approve** (`approveLabel`) | `POST /api/approve` | Bookmark a ruling — **not** apply/commit |
| **Approve** while proposing | `POST /api/approve` then `POST /api/found` | Accept the edited `DESK-PROPOSAL.md` and found the desk. Same word; "Found Desk" was retired by core on 2026-10-01 |
| **Comment** (`commentLabel`) | `POST /api/comment` | Send-back note on the entry |
| **Not this** / **Bring back** (`notThisLabel` / `notThisUndoLabel`) | `POST /api/set-aside` `{project, id[, undo]}` | Set the entry aside, or return it to pending. One press, no prompt. Off during founding/proposing and on the proposal entry (core refuses it with 400; the message is shown as-is). The quietest control |
| **Finish batch** (`sweepLabel`) | `POST /api/sweep` | The sweep (optional thrust). With `kettle.confirmSweep` off the drawer's button arms for 3 s and reads **Undo** (`sweepUndoLabel`) |

**Handled** = `approved` · `rework` · `set-aside` (`project.isHandledEntry`). Handled entries sink to the bottom of the queue and are skipped by "open next".

Ritual order is **decision-first: Approve · Comment · Not this · Finish batch**, left-aligned (side-agnostic — Desk may sit in either sidebar). Gap between buttons is roomy by default and collapses as the panel narrows. Comment opens a drawer **under** the ritual bar into the chat stream (not above the buttons).

**Header chrome:** project selector pill + settings gear + **chat model pill** (from `GET /api/curator/catalog` / `POST /api/curator`). “Browse all…” on the project menu falls back to host QuickPick. No bullseye jump control (selection follows the active editor; `kettle.jumpActive` remains).

**Brief block:** takeaway quote first (curator `ask`, unlabeled), then full brief.

**Ritual enablement** (aligned with core midfoot): Approve/Comment/Not this need an open entry; Approve off when already approved (except proposing); Not this off on the proposal; Finish batch needs a project and stands down while founding/proposing/streaming.

**Status text** is a catalog state (`states.<name>.line`): `interviewing`, `proposing`, `founding` (found stream), `sweeping` (sweep stream), `broken` (queue 409/404), shown after the connection in the status bar item.

Open file = click the path (or Explorer queue). Status/urgency tags, secondary project labels, and the plugin version stamp stay out of the Desk header.

## Webview message types (webview → host)

`ready` · `approve` · `comment` · `notThis` · `sweep` · `chat` · `compact` · `cancel` · `confirmCard` · `settings` · `openEntry` · `refreshDiff` · `selectProject` (`projectId` optional — omit for host QuickPick) · `refreshProjects`

(`jumpActive` remains a command-palette command; the bullseye header control was removed.) Founding interview is started from the host toast or **Kettle: Set Up Project** (`kettle.beginFounding`), not a Desk ritual button.

Host → webview: `state` (includes `projects[]` and tested `ritual` enablement) · `stream` · `activity` · `foundingView` · `streaming` · `freeze` · `ritualZoom`.

## Empty states

- **No project** — show Select project CTA + `kettle add` hint (`body.needs-project`).
- **Project, no entry** — brief invites Explorer selection; ritual Approve/Comment disabled.
- **Interviewing** — hide ritual; show confirm-card pane (start via toast / command).
- **Proposing** — hide Comment / Not this / Finish batch; show pulsing **Approve** + the catalog's proposing copy.

Before approving the proposal calls `/api/approve`, host glue resolves the proposal entry and saves only the dirty `DESK-PROPOSAL.md` editor buffer. A missing proposal or failed save stops both approve and `/api/found`.

## Build id

`DESK_UI_BUILD` / `debug.BUILD_ID` still come from `package.json` `version` and show up in **Kettle: Debug** / the debug log — not as chrome on the Desk.
